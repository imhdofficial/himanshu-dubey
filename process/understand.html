PROCESS / 01 / UNDERSTAND

Understand
before UI.

The fastest way to waste design time is to start drawing before the problem is small enough to reason about. Discovery turns a vague request into a user task, constraints, edge cases and a measurable definition of done.

THE STANDARD

Reduce ambiguity before adding pixels.

A clear brief should let design and engineering make decisions without repeatedly asking what the product is supposed to do.

INPUTBusiness request
OUTPUTPrioritized task map
RISKHidden edge cases

WHAT GREAT LOOKS LIKE
01

Ask what changes for the user

Features are not goals. Identify the before-and-after behavior the product should create.

02

Separate must-have from preference

Business rules, legal constraints and technical limits are different from visual preferences.

03

Find the uncomfortable cases

No data, duplicate actions, invalid input, weak network and interrupted sessions should be considered early.

04

Write acceptance in plain language

Everyone should be able to state what “working” means before implementation starts.

PRACTICAL METHOD
01

Collect the request

Capture stakeholders, audience, desired outcome and current pain.

02

Map the primary task

Write the shortest successful user journey.

03

List constraints

Identify platform, data, device, timeline and operational limits.

04

Expose edge cases

Ask what happens when the happy path breaks.

05

Prioritize

Choose what must be solved now and what can intentionally wait.
